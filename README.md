# JobTrail 职迹

一款本地优先的求职投递进度管理网页。把投递链接或邮箱、公司、城市和招聘进展放在同一张看板里；收到公司的下一步通知后，选择实际环节，系统会自动补充流程与时间线。

## 功能

- 投递档案：公司、岗位、城市、薪资、投递链接或邮箱、标签与备注
- 链接识别公司：粘贴企业招聘官网或包含公司信息的岗位链接后，在浏览器本地尝试填写公司名称
- 截图识别：在新建或编辑投递窗口按 Ctrl + V、点击“粘贴图片”或选择/拖入招聘截图，本地识别公司、工作地点和多个岗位；核对、修改或取消候选后填入表单，详细地址可补到备注
- 动态招聘流程：新建或导入后“已投递”默认完成；收到通知后再添加线下宣讲、在线测试、AI 面试、一面、二面、终面、HR 面或 Offer
- 投递归类：“全部投递 = 进行中 + 已结束”；宣讲、测试、面试与 Offer 可单独筛选，也都计入“进行中”
- 宣讲信息：进入线下宣讲时可填写地点与时间，也可在该阶段单独修改，并直接显示在公司卡片上
- 自动进展时间线：完成、跳过、跨阶段移动、回退、暂停、未通过和撤回都会保留记录
- 独立完成环节：可在详情或“记录新进展”中先将当前宣讲、测评、面试标记为已完成；公司卡片同步显示完成状态，收到通知后再记录真实的下一步
- 岗位与城市多选：同一条投递可添加多个岗位和多个城市，并以标签逐项移除
- 手动常用选项：可一次添加多个岗位或城市候选、连续点选或取消、逐条删除；普通填写和导入不会自动生成选项，公司名称不记录候选历史
- 看板与列表双视图：支持搜索、城市筛选、阶段筛选和快捷状态筛选
- 跟进工作栏：所有已设置跟进日期的有效投递会进入侧边栏交叉筛选；到期记录还会出现在首页提醒区并在卡片上突出显示
- 拖动更新：桌面端可把卡片拖到该公司流程中的目标阶段，跨过的环节自动记为跳过
- 本地持久化：数据保存在浏览器 `localStorage`，不上传到服务器
- CSV 投递导入：识别单位、岗位、城市 / 工作地、投递链接或邮箱、状态、测评 / 笔试和投递日期
- 智能状态转换：把已投递、线下宣讲、线上测评、AI 面、一面、拒绝和人才库转换为 JobTrail 动态流程
- 备份迁移：支持 JSON 完整备份的导入/合并，以及 CSV 导入与导出
- PWA 与离线访问：可安装到电脑桌面并离线打开
- 深色模式、键盘快捷键与电脑端大屏看板

## 本地运行

无需安装第三方依赖，只需 Node.js 20 或更高版本：

```bash
npm start
```

然后访问 <http://127.0.0.1:4173>。

也可以直接使用任意静态文件服务器托管项目根目录。由于页面使用 ES Modules，不建议直接双击 `index.html` 以 `file://` 方式打开。

## 测试

```bash
npm test
npm run check
```

当前自动化测试覆盖链接识别公司、截图文字字段提取、动态流程、自动推进、跳过环节、跨阶段移动、回退重开、终止状态、跟进日期、统计、备份合并、CSV 解析、字段白名单、去重和进度转换。`scripts/browser-smoke.mjs` 还可连接 Chrome DevTools，执行真实浏览器烟雾测试。安装开发依赖后，可用 `node scripts/recognize-image.mjs 图片路径` 在本机验证真实截图识别效果。

## 数据与隐私

投递信息只保存在当前浏览器和当前站点域名下。CSV 文件由浏览器本地解析，未识别的列不会写入 JobTrail，文件也不会上传。清理浏览器数据、切换域名或更换设备都可能看不到原记录，因此建议定期点击“导出数据”保存 JSON 备份。

## 从招聘截图填写

在“新建投递”的“从招聘截图填写”区域粘贴图片，或点击“选择图片”、拖入图片。识别后确认公司名称，勾选需要的城市和岗位，点击“填入表单”，最后保存投递。岗位和城市追加到当前已选项，不会自动保存到手动常用选项；图片本身不保存到投递记录或上传到服务器。详细工作地址可选择追加到备注。

中文识别使用随站点提供的 Tesseract.js 与中文模型，首次使用需加载约 6 MB 资源，之后可复用本地缓存。支持 PNG、JPG、WebP 等截图，单张不超过 20 MB。小字、模糊图或复杂排版可能产生错字，建议裁剪招聘信息区域并核对结果；也可修改“识别文字”后重新提取字段。剪贴板按钮不可用时，可直接按 Ctrl + V 或选择图片。

OCR 资源已随仓库提供，普通运行不需安装依赖。需要更新这些第三方资源时，运行 `npm ci --ignore-scripts` 和 `npm run prepare:ocr`；版本与许可证见 [vendor/ocr/README.md](vendor/ocr/README.md)。

## 导入投递 CSV

点击侧边栏“导入投递 CSV”并选择 `.csv` 文件。支持以下常见列名：

- 公司：`单位`、`公司`、`公司名称`、`投递公司`
- 岗位：`岗位`、`岗位名称`、`职位`
- 城市：`城市|工作地`、`城市/工作地`、`城市`、`工作地`
- 链接或邮箱：`投递链接`、`链接/邮箱`、`岗位链接`、`邮箱`
- 进度：`状态`、`目前的进度`、`测评|笔试`
- 日期：`投递时间`、`投递日期`

公司和岗位为必需列。缺少这两项的行会跳过；没有投递日期时，页面会先提示并在确认后使用导入当天。重复导入同一批记录不会重复创建时间线。备注、附件、简历等未识别列会忽略。

## 部署到 GitHub Pages

仓库包含 [`.github/workflows/pages.yml`](.github/workflows/pages.yml)。推送到 `main` 后：

1. 打开仓库的 **Settings → Pages**。
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
3. 重新运行 `Deploy JobTrail to GitHub Pages` 工作流（或再次推送）。

工作流会先运行单元测试，测试通过后再发布静态网页。

## 快捷键

| 快捷键 | 操作 |
| --- | --- |
| `N` | 新建投递 |
| `/` 或 `⌘ K` | 聚焦搜索 |
| `E` | 导出 JSON 备份 |

## 项目结构

```text
job-application-tracker/
├─ index.html                 # 页面结构与对话框
├─ styles.css                 # 电脑端大屏与深色模式样式
├─ src/
│  ├─ app.js                  # 界面渲染与交互
│  ├─ csv-import.js           # CSV 解析、字段映射、去重与进度转换
│  ├─ model.js                # 流程、时间线和数据规则
│  └─ storage.js              # 本地持久化
├─ tests/                     # Node.js 单元测试
├─ scripts/
│  ├─ dev-server.mjs          # 零依赖静态开发服务器
│  └─ browser-smoke.mjs       # Chrome 真实浏览器烟雾测试
├─ sw.js                      # 离线缓存
└─ .github/workflows/pages.yml
```
